# AGENTS.md

## Cursor Cloud specific instructions

This repo is a governed multi-agent orchestration system (SGRS): TypeScript orchestration + a
Rust `napi` kernel (`sgrs-core`), with a Python facts-worker and a Docker-based service stack.
The notes below capture non-obvious setup/run caveats for this Cloud environment. Standard
commands live in `README.md`, `CONTRIBUTING.md`, and `package.json` `scripts` — refer to those
rather than duplicating them.

### Toolchain (already provisioned in the base VM)

- **Node 24** is required (`package.json` `engines.node >=24`; CI + `@napi-rs/cli` need it).
  The base VM ships an `/exec-daemon/node` (v22) that shadows `nvm` in `PATH`. Node 24 is
  installed via `nvm` and symlinked into `/usr/local/cargo/bin` (first in `PATH`) so `node`,
  `npm`, `npx`, `pnpm`, and `corepack` resolve to the Node 24 toolchain by default. If a future
  shell somehow reports Node 22, run `nvm use 24` or re-create the symlinks in
  `/usr/local/cargo/bin`.
- **pnpm 10.30.1** via corepack (pinned by `packageManager`).
- **Rust stable must be >= 1.85** (edition 2024). `sgrs-core`'s napi dependency chain
  (`wit-bindgen`) fails to compile on older toolchains. The VM's `rustup` default has been
  updated to current stable (1.98).

### Build order matters on a fresh checkout

`sgrs-core/index.js` and `sgrs-core/index.d.ts` are **generated by `pnpm build:rust`** and are
consumed by `tsc`/ESLint. On a clean checkout they do not exist yet, so always run the Rust
build first:

```bash
pnpm build:rust   # compiles the Rust kernel + generates sgrs-core napi bindings
pnpm build        # tsc -> dist/
pnpm typecheck    # needs sgrs-core typings (after build:rust)
pnpm lint         # eslint (type-aware; needs sgrs-core typings). Passes with warnings (--max-warnings 80)
pnpm format:check
pnpm test         # vitest; unit tests mock the DB/NATS, so no services are required
```

Rust kernel tests (the deepest coverage) run independently of Node:
`cargo test --manifest-path sgrs-core/Cargo.toml`.

### Running things without the Docker stack

The core convergence/governance engine runs with **no Docker and no LLM key**. Good smoke test /
hello-world:

```bash
npx tsx scripts/benchmarks/benchmark-convergence.ts   # synthetic convergence scenarios (11/11)
```

### Full swarm / demo requires extra infrastructure (not in the base VM)

`pnpm run demo` (UI :3005), `pnpm run swarm:start`, `pnpm run feed` (feed + Studio :3002), and
`./scripts/ops/run-e2e.sh` depend on the `docker compose` stack (Postgres + pgvector, NATS
JetStream, MinIO/S3, OpenFGA, OTEL/Prometheus/Grafana, facts-worker) plus an LLM for fact
extraction (`OPENAI_API_KEY`, or local Ollama via `FACTS_WORKER_OLLAMA=1`). **Docker is not
installed in the base VM**, and no LLM key is configured, so the full end-to-end demo is not
runnable out of the box. To enable it: install Docker, `cp .env.example .env` and set
`OPENAI_API_KEY`, then follow the Quick Start in `README.md`
(`docker compose up -d` → `ensure-schema`/`ensure-bucket`/`ensure-stream` → `seed:all` →
`bootstrap-once` → `swarm:start`). The demo server can be started UI-only with
`DEMO_SKIP_PREFLIGHT=1`, but taking demo actions still needs the running swarm.
